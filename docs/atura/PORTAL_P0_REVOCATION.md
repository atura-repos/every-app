# P0 — membership and role revocation at the Gateway

## Strategy and bound

`resolveOrgContext` no longer caches **positive** membership or role in an isolate. Every subsequent authorization that calls it reads the current membership from D1 (including the session's active organization and sole-organization fallback). The Gateway's `organizationMemberMiddleware` and `organizationAdminMiddleware` protect direct member/admin server functions; the app-host authenticator also calls the same resolver before issuing identity to an app, including membership in another organization. A changed role or deleted membership therefore takes effect on the **next authorization read after the D1 write is visible**, even when that read lands on an isolate that did not perform the write. There is no 30-second *positive membership* TTL. An in-flight request that already passed authorization is not interrupted, and this is not a wall-clock/propagation SLA for D1 or Better Auth sessions.

Negative membership results remain cached per isolate for at most 30 seconds (maximum 500 entries): a newly granted member may be denied temporarily, but a stale denial cannot confer access. `forgetOrgContext` clears the writing isolate's denials; other isolates age them out. `isOrganizationActive` still caches organization suspension status for at most 30 seconds per isolate; suspension revocation is **not** immediate and needs a separate security-owner decision. App registry, group/grant, token and browser caches are separate controls; this change does not claim immediate revocation for them. Session deactivation relies on Better Auth's session validity and ban checks, not on a cached org role.

Cost: one membership D1 lookup per authorized context resolution, rather than one per 30 seconds per isolate. Denied requests retain their negative-cache shortcut; organization-status caching is unchanged. No production latency benchmark or multi-isolate Cloudflare measurement was performed locally.

## Local evidence

- Unit: `src/server/organization/orgContext.test.ts` simulates a second isolate changing admin to member and then deleting membership, **without** local cache invalidation; both next requests read the new state. The downgrade and removal assertions failed against the old positive cache before the change, then passed.
- Migrated SQLite: `src/server/user-management.sqlite.test.ts` changes the member row directly without clearing this isolate's cache and verifies the direct-API resolver now returns member, then null.
- Runtime-equivalent app-host fixture: `src/server/third-party-hosts.sqlite.test.ts` uses real Better Auth sign-in, the Worker entry, migrated SQLite and the app-host session. The identity delivered on the next request changes from owner to member after an out-of-band write without clearing the cache. Its authenticated `/app-session/start` POST refuses sibling-origin and absent-origin requests (403) and accepts a same-origin request (303). This exercises a real state-changing control-plane route, **not** TanStack's generated `/_serverFn` mutation endpoints; those still require a separate browser/runtime check before security sign-off.

These are deterministic local checks, not a Cloudflare multi-isolate or live-tenant test. After combining the branch changes, the Gateway unit suite passed (155 files, 1,388 tests), the migrated SQLite integration suite passed (51 files, 803 tests), and the Gateway typecheck and build passed. These are local checks, not a Cloudflare multi-isolate or signed-in tenant test. No deploy was performed. A security owner still needs to approve the suspension/other-cache bounds and a live revocation SLA before pilot sign-off.
