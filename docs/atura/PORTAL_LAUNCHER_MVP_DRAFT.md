# Atura unified launcher MVP — draft implementation notes

This branch is based directly on the independently reviewed, **unmerged** P0 PR #14 head `826f6a4fb7f64f5b57f17de6fe2e6e358aa2ce2e`. It is a dependent draft PR, not authorization to merge or deploy either PR.

The home screen now projects authorized managed apps, Atura-published links and own links into one filtered search/count and a single placement per key. Name and description only are searched; URL paths and queries are not search terms. Managed MCP-only actions still open their existing instructions dialog, not a website. Pinning is independent of collection membership; unpinning returns an item to its collection. The page waits for all three sources and preferences to revalidate; on a source error it displays a named incomplete-list error and no potentially stale cards. This is stricter than the phase-0 proposal to display only the successful sources. Existing query hooks still exclude private data from browser persistence and gate data on fresh session/source checks.

`0027_portal_collections.sql` adds default-empty JSON collections and assignments to the existing per-workspace, per-user preference row. The existing CAS revision guards all layout changes. Old clients omitting these optional fields do not erase collections; older managed IDs remain readable and are projected as `managed:<id>`. A missing or revoked typed source never yields a tile from saved preferences. New collection assignments require live authorization at save time; a revoked assigned key can block subsequent saves until the user resets the layout. Reset changes only the preference row, not links or publications. No SSO/Graph/Entra tile, hide feature, icon upload or destination fetch is added.

**Review risks:** The design uses native prompt/confirm for rename, delete and reset; manual screen-reader, focus restoration, 200%-zoom and 320/375-px browser checks remain necessary. The link symbols are built-in by type; configurable icon choices and a letter fallback for malformed icon identifiers are not implemented. In-flight save status is provisional until the CAS response; do not infer save success from the optimistic UI. Legacy `sort` in localStorage was already discarded by the pre-existing import path. Browser sign-in and two-user/two-workspace acceptance have not been performed in a live tenant. Privacy retention/offboarding/log access/DPIA, revocation latency across isolates and an explicit owner acceptance remain separate gates.

No CLI/MCP parity row is added: this branch introduces no server function or administrative tab. No live Cloudflare, Entra, staging or pilot action was run.
