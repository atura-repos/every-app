# Maester-dashboard (Atura pilot)

Private EveryApp-managed app with scheduled GitHub App reconciliation every six hours, a normalized read model, and an Atura-branded PDF concept with explicit employee approval. No public ingest route, scan trigger, customer login, automatic email or customer delivery. GitHub Actions artifacts expire after ~14 days.

## Security boundary

- Gateway authentication **and a narrow app grant** are prerequisites. No everyone/org-wide grant. Every read checks SDK-signed identity: exact `mvanfalier@atura.nl`, configured `PILOT_USER_ID` and `PILOT_ORG_ID`, `web` channel, actor=user, and explicit `(tenant_id, org_id, user_id)` row in app D1. Unknown/missing settings fail closed. Verify direct-URL denial for another member in staging. The pilot's immutable Gateway IDs are supplied as app secrets, never guessed or seeded.
- Own D1 `DB` and private R2 `REPORTS`, never Gateway D1. Operators provision one `github_repositories` row per immutable repo ID/tenant identity (owner/repo and installation ID), then one `github_sources` row per allowed workflow ID with exact `workflow_path`, `workflow_ref`, artifact prefix and enabled status. The composite `(repo_id, workflow_id)` key permits daily + three CIS workflows without permitting a second tenant for the same repository; a database trigger prevents rebinding the repo ID/tenant. Migration 0005 preserves legacy source rows but disables them with an empty path: verify and set each path before explicitly re-enabling. No tenant/source is seeded. Allowed prefixes: `maester-atura-dashboard`, `maester-atura-cis-graph-dashboard`, `maester-atura-cis-exo-dashboard`, `maester-atura-cis-teams-dashboard`. Configure GitHub App with repository-restricted Actions/Metadata read-only, install only on approved private repositories; supply `GITHUB_APP_ID` and `GITHUB_APP_PRIVATE_KEY` as app secrets, not a PAT.
- Only a matching run-ID-named `dashboard-result-v1.json` projection is parsed, paired with a same-run legacy artifact. Six exact top-level keys, bounded IDs/statuses and ZIP, no source titles, evidence, error records or raw JSON. Repository, workflow ID, path and branch mismatch, invalid scope and unexpected fields fail closed. GitHub currently emits a bare run `path` in live metadata; when a suffix is present it must match the registered branch, while bare paths rely on `head_branch` for branch identity. Legacy HTML/Markdown is **not** imported and never displayed inline. Missing projection records `projection_missing` in the tenant-scoped import-status panel. R2 readback verifies normalized projections by digest; D1 indexes repository/run/attempt/artifact id. On an uncertain D1 batch/readback, reconciliation retains R2 to avoid a broken committed index and attempts to record `readback_unverified`; a separate D1 `pending_r2_objects` ledger is written **before** each R2 upload so even an unindexed object is swept at the one-year expiry. Rerun attempts without artifact-attempt provenance are skipped.
- Controlled HTML is a **derivative, never legacy original bytes**. The separate private `controlled-original-v1` artifact is compared byte-for-byte with a canonical reconstruction from the allowlisted projection and workflow/run metadata. D1 `controlled_original_index` and R2 retain only the matching derivative; the pre-write `pending_r2_objects` ledger and one-year expiry include it. A missing/invalid controlled artifact never makes an unsafe legacy fallback. The pilot downloads it only as an authenticated, digest-verified `application/zip` attachment via `/api/controlled-original`; no HTML response is served on the app origin. A stale/missing artifact yields a tenant-scoped safe status. Live GitHub and Worker transport remain to be proven in staging.
- The read model preserves Passed/Failed/Skipped/NotRun/Error, scan status and workflow conclusion separately. Comparisons require matching tenant, suite, benchmark and expected ID set; technical scans are not comparable. Source titles are absent; displayed IDs are not semantic benchmark version metadata. Do not use for customer reporting until semantic definitions/versioning are established.
- `/api/reports` is intercepted within the SDK-verified Worker; each status, creation, approval and download checks the exact pilot identity and tenant grant. POST requires same-origin JSON. Concepts use allowlisted normalized D1 fields only, with R2 PDF bytes and D1 digest/SHA-256/version/audit. Approval is explicit, per source digest, and a source change invalidates the download. The pilot may approve their own concept. Approved PDF is attachment-only with integrity readback; `CONCEPT` remains visible even after internal approval. No customer email or automatic distribution.
- One-year retention from scan creation first locks the run against new PDF versions, then deletes normalized and PDF R2 objects, D1 rows and approval actor events and writes a retention audit event. A failed R2 deletion is retried on the next scheduled pass. Reconcile backup retention before release. At most 100 recent runs per registered source (20 sources maximum) are scanned; older/backlogged runs require separately reviewed backfill. Actual scheduled GitHub/D1/R2 operation, Access, app grants, PDF rendering and negative tenant tests remain to be proven in staging. No customer onboarding or production release is authorized by this code alone.

## Local verification

`pnpm -C apps/maester-dashboard test`, `pnpm -C apps/maester-dashboard build` and `pnpm -C apps/maester-dashboard format:check` from repository root. Tests use in-memory SQLite and fictional identities; generated migrations contain no tenant seed. Review the combined migration chain before deployment. The PDF embeds a PNG derived from the official `atura-logo-kleur.svg` asset; CSS tokens use the official navy/teal. Production design/accessibility review remains necessary.
